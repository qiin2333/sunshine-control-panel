# 原生侧载组件接入合同

本文规定 Panel 管理原生组件时的身份、所有权、文件与操作边界。具体组件仅能提供实际实现的操作；
注册表中出现组件，不代表该组件已经具备下载、安装、加载或运行能力。

## 身份与所有权

- 组件使用编译期固定 ID；界面只传组件 ID、源文件角色和受支持的业务参数。
- 宿主表示实际使用组件的进程，例如 GUI 或 Sunshine Core。
- 执行方式、文件角色、功能能力和分发方式分别声明，不以一个类型字段混合表达。
- 项目内部适配代码属于实际宿主的实现，不作为用户可导入或删除的第三方组件。
- Panel 负责管理交互和安装编排，实际宿主负责运行生命周期与最终接受判断。

同一个组件可以提供多个能力，各能力的业务接口独立版本化。厂商运行库不需要实现 GUI 工具 ABI。
GUI 工具插件继续遵守 [原生工具插件协议](native_tool_plugin_development.md)。

## 文件与信任

每个文件角色声明固定名称、架构、大小限制、允许来源和更新归属。组件安装不能覆盖宿主自身文件。
可信摘要来自宿主的构建输入或既定可信发布机制；配置文件和安装记录不能自行扩展允许执行的代码集合。
构建期校验不替代运行时加载前验证。文件名、PE 格式和 ABI 正确也不能单独证明文件来源。

Panel 可以预检用户选择的文件。实际宿主仍须确认目标文件符合自身支持的版本，不能直接信任
Panel 提交的“已校验”标志。校验实现可以由内置厂商适配层调用公共文件校验能力。
未知文件被拒绝时不得通过临时加载来试探是否兼容。

安装记录可使用 JSON 保存文件角色、实际版本和事务结果；它是可恢复状态，不是执行授权来源。
宿主模块的 build identity 与第三方运行库的 artifact identity 分开，运行库未改变且仍受支持时，
升级宿主不应要求用户重复导入。

## 操作与状态

通用操作包括查询、导入、修复、移除和恢复。下载只对明确支持此分发方式的组件开放。
组件选择、功能启用和业务参数归业务配置，不将所有组件强制设置为同一种自动启用策略。

状态分别表达安装状态、维护操作、配置状态及实际运行结果。文件安装成功不能等同于设备或功能运行成功。
错误使用稳定分类，面向用户的信息不直接包含本地路径、请求 URL 或系统异常原文。

安装编排遵循：预检源文件 → 协调宿主维护 → 必要时 UAC → 暂存和目标校验 → 提交文件与宿主状态 → 结束维护。
恢复须查询实际持久状态；超时或响应丢失不能直接推断助手已经退出或写入一定失败。
组件仍被使用时不得覆盖或删除文件，也不得由 Panel 结束不属于自己的业务会话。

## 加载与关闭

组件由实际宿主按需加载，加载路径和允许的文件角色来自固定描述。
加载前校验与实际执行必须针对同一个文件；模块引用覆盖所有实例、线程、GPU 工作和回调的存活期。
全局注册表锁不得覆盖插件导出函数、GPU 操作或长期停止等待。
正常工作时不逐帧执行摘要计算、安装探测或管理 API 请求。

关闭管理页面不会隐式停止 Core 组件。GUI 工具停止和卸载遵守自己的 ABI，
独立进程组件遵守进程控制合同，不能把 DLL 的 FreeLibrary 语义套用到所有组件。

## 构建与兼容

适配代码可以静态内置，也可以因 SDK 工具链要求使用内部桥接模块；该编译选择不改变用户的管理对象。
静态接入必须验证实际 SDK 客户端、ABI 和运行库依赖，不能只根据第三方 DLL 存在就推断可以直接动态调用。
对整文件摘要进行固化时，签名等会修改文件的处理必须在该文件摘要冻结之前完成。
公开的支持版本、最终安装文件和实际宿主内的接受策略必须一致。
